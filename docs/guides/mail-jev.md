# 邮件工作台 Jev 自动复核

## 一次设置

1. 在 https://console.typesafe.ai/ 创建 API Key，并确认账户可用额度。
2. 在**实际接收邮件的 Windows 电脑**双击仓库根目录的 `设置邮件Jev.bat`，粘贴密钥，点击“测试连接并启用”。测试只发送一条虚构消息，产生一次 API 调用。
3. 重新启动原有邮件接收程序。只重启网页不能更新接收进程的配置；接收电脑仍需在线、邮箱认证和 Codex 登录仍需有效。

密钥保存为当前 Windows 用户的 `TYPESAFE_API_KEY` 环境变量，开关为 `MAIL_JEV_ENABLED`；同一用户的其他进程可以读取它。不会写入源码、Git 或邮件快照。已有进程环境优先于用户环境，因此修改后应重启接收程序。其他电脑或服务账户需各自设置。无需安装新依赖。

## 每次使用

登录邮件工作台编辑权限后，点击一次“立即收信”。原有接收程序会自动完成：

收取新邮件 → Codex 整理 → 原文摘录和日期校验 → Jev 复核 → 保存并同步。

页面在本次收信期间每 15 秒自动更新进度，不必反复点击刷新。浏览器关闭不会取消已提交的收信任务；重新打开后查看结果。此功能沿用现有按需收信机制，**没有额外安装定时收信任务**。

- 证据支持、适用对象明确、确定需要处理的事项自动进入“待办”。
- 没有待办且明确仅供知悉的邮件自动进入“无需处理”。
- 条件性或自愿任务、语义矛盾、疑似遗漏、缺失/截断附件、推断年份等保留“待判断”。
- 可先看“待判断”解决疑点，再看“待办”处理工作；选择状态后自动保存。
- 所有自动分类都可以改回。人工既有判断、旧摘要和已完成事项不会重跑或覆盖。

## 注意事项

- 启用后，新邮件正文、已读取的附件文字和整理结果会发送到 TypeSafe。不会发送邮箱密码、附件原文件或本机路径；正文里原有的个人信息仍可能随内容发送。处理不宜交给该服务的邮件前应关闭自动复核。
- Jev 复核是辅助判断，不证明内容真实，也不保证查出全部遗漏。初期应抽查“无需处理”邮件及自动进入“待办”的事项。当前阈值是保守的初始工程设置，未经本学院数据校准，不是准确率保证。
- 摘录匹配、日期格式、原件保留、状态并发保护仍由代码检查。Jev 不发送邮件、不报送材料、不自动标记完成、不自动存档附件。
- 只复核新邮件。无密钥、关闭开关、接口报错、超时或返回异常时，保留原整理结果并显示未复核状态，不把它当作通过，不中断正常收信。
- 每封新邮件通常调用一次，独立判断放在同一请求；最多 4 封并行，临时限流/繁忙最多重试一次，单批调度预算 120 秒，已发出的请求最多再等待连接/读取超时。超过文字上限或预算的保留待判断，不自动反复付费重跑。
- API 用量按 TypeSafe 账户计费；本功能不保证总成本或耗时低于原流程。Codex 原来的整理调用仍保留。

## 关闭

再次打开 `设置邮件Jev.bat`，选择“关闭自动复核”，重启接收程序即可。已有分类和人工修改不受影响，也不删除密钥。
