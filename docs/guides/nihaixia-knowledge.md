# M32 倪海厦知识库

入口位于工具箱“个人”分类。使用现有 `budget_password` / `BUDGET_PASSWORD`，页面验证密码后才读取知识正文。
公共仓库仅包含展示程序与整理工具，正文只存于指定私有数据仓库 `yaoy2/yao_1-data` 的 `data/nihaixia/`。

## 内容组织

总纲与合参方法、紫微命身与六亲、大限小限与流年、四柱命卦、易经与人间道、阳宅与地脉、各家补充支系、命例与条件对照。
规则完整保留判断、条件、例外、推导、归属、出处及原始结构。专题保留连续解释与矩阵，条件对照单独检索。
明确剔除过程统计、分工、校验流水、原书原片、读取快照与旧备份。只有完全相同的正文合并来源。

## 手动更新

只有用户明确发出更新或发布指令才执行。没有定时更新、自动研习、网页编辑或后台写入接口。

用户指令示例：

> 更新倪海厦知识库：把上次发布后新学的内容按主题并入，保留条件、例外、推导和出处，核对后同步到 GH 与 M32。

1. 使用原知识库项目环境运行 `scripts/build_nihaixia_library.py build --source-root <知识库项目> --output <知识库项目/data/publication/current> --date YYYY-MM-DD`。
2. 对照 `coverage_audit.json`、`source_inventory.json` 和新增／修正内容。构建器复核所有接受记录，失效笔记会阻断发布；原始语料只读。
3. 检查新增字段、主题归属、未决问题与已纠正旧说。通读新专题；若有新的工程记录标题，调整过滤并核对省略段落中没有理论内容。
4. 只有通过核对后才运行同脚本 `publish --output <构建目录>`。发布前读云端；少了已发布条目会停止。新版本各分卷逐个上传、回读，最后按预期 SHA 切换目录。
5. 回读全库并核对版本、条目和规则数。页面“刷新版本”读取已经发布的版本，不触发整理或写入。

若新增知识在其他位置，先将经过理解的笔记并回原项目，勿把整个目录或原始素材上传。
编辑导读置于原项目 `data/publication/editorial/`，不进入公开代码仓库。

## 验证与恢复

`tests/test_nihaixia_knowledge.py` 覆盖目录／分卷校验、搜索、私有仓库要求和页面密码门禁；使用 Streamlit AppTest，不启动本地服务。
分卷按内容版本固定保存，目录指向的每一卷必须校验通过。发生冲突停止覆盖；旧版本分卷仍保留。
运行时沿用已有 GitHub 连接与统一密码，不新增密钥；日志和错误消息不输出凭据或正文。
