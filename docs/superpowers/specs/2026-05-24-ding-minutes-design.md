# Ding 文件纪要登记板块设计

## 目标

新增板块 11，用于每天自动扫描 `Ding2026` 文件夹中的钉钉导出 Word 转写文件，将符合规则的新文件登记为可检索记录，并调用 DeepSeek 生成有价值的整理稿。

这个功能解决三个问题：

- 不再靠人工记得整理钉钉导出的 `docx` 文件。
- 将碎片化、口语化、重复度高的转写文本加工成可归档、可复盘、可继续写材料的整理稿。
- 保证从当前 D 台式机迁移到 L 电脑后，只需要改本机配置和密钥环境变量，不改业务代码。

## 扫描规则

扫描目录从配置读取，默认建议为：

```ini
watch_dir = E:\GoogleDrive\Ding2026
```

每日任务计划在 19:00 运行一次。每次运行时，脚本检查前一天 19:00 到当天 19:00 之间新建的文件。

只处理满足以下条件的文件：

- 扩展名为 `.docx`
- 文件名匹配 `export_*.docx`
- 或文件名匹配 `dt*.docx`
- 文件创建时间落在本次扫描窗口内

同一文件不会重复登记。去重依据使用文件路径、文件创建时间、文件大小和内容指纹组合判断，避免文件重名或迁移后路径变化导致误判。

## 数据保存

新增独立数据库，例如：

```text
data/ding_minutes.db
```

数据库保存以下字段：

- 文件名
- 文件路径
- 文件创建时间
- 文件修改时间
- 文件大小
- 内容指纹
- 原始转写正文
- AI 整理稿
- DeepSeek 模型名
- 处理状态：`pending`、`done`、`failed`
- 错误信息
- 创建时间
- 更新时间

数据库文件不提交到 GitHub。项目当前 `.gitignore` 已忽略 `*.db`。

## AI 整理原则

AI 输出不使用固定八栏目模板。因为钉钉转写可能来自会议、座谈、访谈、培训、工作布置、汇报、讨论或临时沟通，固定格式会损失信息。

DeepSeek 提示词应要求模型根据原文自然组织内容：

- 清理明显的口水话、重复表达、无意义语气词。
- 保留原意，不补充原文没有的信息。
- 根据内容自动判断适合的标题和小节。
- 把碎片化表达整理成连贯、可阅读的段落。
- 提炼对后续工作有价值的信息，例如背景、观点、结论、任务、分歧、待确认事项。
- 对原文不清楚或可能识别错误的地方明确标注“不确定”。
- 输出风格应适合行政归档、复盘和二次写作，不写成机械摘要。

如果原文很短或信息不足，AI 应直接说明“可整理信息有限”，并保留必要原文线索。

## DeepSeek 接入

使用 DeepSeek Chat Completions 接口。模型名从配置读取，默认：

```ini
model = deepseek-v4-pro
```

API key 只允许从本机环境变量读取：

```text
DEEPSEEK_API_KEY
```

不在代码、配置文件、日志、数据库、测试数据、设计文档或提交记录中保存真实 API key。

如果没有配置 `DEEPSEEK_API_KEY`，扫描脚本仍可登记文件和原文，但状态标记为 `pending` 或 `failed`，页面提示“未配置 DeepSeek API key，尚未生成整理稿”。

## 密钥安全规则

为了避免 API key 泄露到 GitHub，执行以下约束：

- 仓库中只出现环境变量名 `DEEPSEEK_API_KEY`，不出现真实 key。
- 不创建包含密钥的 `.env`、`.streamlit/secrets.toml` 或其他本地凭据文件。
- 如果将来需要示例配置，只能写占位符，例如 `your_key_here`，不能写真实值。
- 日志不打印请求头，不打印 API key，不打印完整错误对象。
- 页面不显示 API key。
- 测试只使用假的短字符串，例如 `test-key`，不使用真实格式的 key。
- 提交前用搜索确认仓库里没有疑似真实密钥。

## 配置与迁移

新增普通配置文件，例如：

```text
config/ding_minutes.ini
```

该文件只保存可公开配置：

```ini
[ding_minutes]
watch_dir = E:\GoogleDrive\Ding2026
daily_run_time = 19:00
model = deepseek-v4-pro
```

迁移到 L 电脑时，流程为：

1. 在 L 电脑拉取 GitHub 仓库。
2. 根据 L 电脑实际路径修改 `watch_dir`。
3. 在 L 电脑设置系统或用户环境变量 `DEEPSEEK_API_KEY`。
4. 创建 Windows 任务计划，每天 19:00 运行扫描脚本。

代码不绑定 D 电脑路径。默认路径只是初始配置，用户可修改。

## 板块 11 页面

新增 Streamlit 页面，命名沿用现有页面排序方式，作为第 11 个板块。

页面提供：

- 最近处理记录列表。
- 按日期、状态、关键词筛选。
- 查看原文。
- 查看 AI 整理稿。
- 失败记录的错误提示。
- 手动扫描按钮，用于临时补扫当前时间窗口。
- 对未配置 API key 的明确提示。

页面不负责定时运行。定时运行由 Windows 任务计划完成，页面只负责查看和手动触发。

## 脚本与任务计划

新增独立脚本，例如：

```text
scripts/scan_ding_minutes.py
```

脚本职责：

1. 读取配置。
2. 计算扫描时间窗口。
3. 查找符合规则的 `.docx` 文件。
4. 提取 Word 正文。
5. 写入数据库。
6. 调用 DeepSeek 生成整理稿。
7. 更新处理状态。

Windows 任务计划只调用这个脚本。这样定时逻辑和业务处理分开，迁移到 L 电脑时更容易排查问题。

## 错误处理

常见错误需要可判断、可恢复：

- 文件夹不存在：记录错误，页面提示检查 `watch_dir`。
- Word 文件正在同步或被占用：本次跳过或标记失败，下次可重试。
- Word 正文为空：登记文件，但标记“原文为空或无法提取”。
- 未配置 API key：登记原文，不生成整理稿。
- DeepSeek 请求失败：保留原文和错误摘要，支持后续重试。
- 网络超时：不丢记录，状态标记为失败。

错误日志只记录必要排查信息，不记录密钥。

## 验证方案

不启动 Streamlit 做页面验证，遵守项目规则。

优先做以下验证：

- 用临时目录构造 `export_*.docx` 和 `dt*.docx`，验证扫描时间窗和文件名匹配。
- 验证非匹配文件不会被处理。
- 验证重复文件不会重复登记。
- 验证无 API key 时不会泄露或崩溃。
- 验证 DeepSeek 调用层可用假客户端测试，不在测试中访问真实 API。
- 对新增 Python 文件运行语法检查。

涉及页面展示的部分做代码级验证，视觉风险在交付时说明，不启动 Streamlit。

## 不做的事

第一版不做实时监听文件夹。

第一版不做多模型管理。

第一版不把真实 API key 写入任何配置文件。

第一版不自动删除、移动或改名 `Ding2026` 中的原始文件。

第一版不把生成的整理稿自动发邮件、发微信或发布到外部平台。
