# M20 Ding2026 只读展示页设计

> 状态（2026-08-31）：M20 已按本设计实现。随后同日加入 M21 并重做首页分区导航，因此下文“19 个模块、M20 首位、9 张卡片分页”等数量与排序描述仅保留为实施前历史基线；当前答案以 `hello.py`、README 和 `docs/repository-structure.md` 为准。

## 目标

在 `yao_1` 的 Streamlit 工具箱中新增 M20，用一个只读页面说明独立私有仓库 `ding2026-system` 解决什么问题、具备哪些能力、如何在本地使用，以及当前项目状态。

M20 是展示层，不是 Ding2026 的控制台。实际文件治理逻辑、配置、数据库和运行入口继续只存在于独立仓库 `E:\github\ding2026-system`。

## 用户合同

- 首页和自定义侧栏出现 M20“Ding2026 文件治理系统”入口。
- 页面文件位于 `pages/19_20_ding2026.py`。
- 页面清楚回答三个问题：为什么需要它、它能做什么、日常怎么用。
- 页面只读取随 `yao_1` 部署的脱敏静态快照，不读取本机数据库、Google Drive、业务目录或独立仓库。
- 页面不提供归档、分发、撤销、配置、刷新、上传、下载或打开本地控制台的操作入口。
- 页面不得展示文件名、人员信息、真实业务路径、令牌、配置值或数据库内容。

## 不在范围内

- 不把 `ding2026-system` 的 Flask 控制台、扫描器、分类器或数据库代码复制进 `yao_1`。
- 不在 Streamlit Community Cloud 上运行文件扫描、分发或规则学习。
- 不建立跨仓库实时同步、GitHub API 读取或私有仓库令牌。
- 不修改 Ding2026 的归档规则、配置和本地运行行为。
- 不启动本地 Streamlit 服务做视觉验证；遵循项目现有规则，只做代码级和纯函数/静态结构验证。

## 方案选择

采用“单页展示 + 本地静态快照”。

- `pages/19_20_ding2026.py` 负责页面结构与说明文字。
- `assets/ding2026_m20_snapshot.json` 保存可公开的聚合数字、版本和快照时间。
- `hello.py` 负责 M20 首页卡片；现有 `utils/ui_theme.py` 自动从 `hello.py` 生成侧栏，不新增第二份导航配置。

不采用运行时读取 `E:\github\ding2026-system`，因为线上部署没有该路径；不采用运行时读取 GitHub 私有仓库，因为会引入令牌、网络故障和权限风险。

## 页面信息架构

页面沿用主工具箱的全局主题、宽屏布局和固定返回首页/侧栏导航。内容保持紧凑，长说明使用标签页或展开区承载。

### 1. 项目概览

- 标题：M20 · Ding2026 文件治理系统。
- 定位：面向学院行政材料和 Google Drive 同步目录的本地文件治理系统。
- 原则：规则优先、手动分发、抽样验证、全程可撤销、永不自动删除。
- 明确标识“本页仅展示；真实操作只在 Windows 本地项目中进行”。

### 2. 它解决什么问题

用短卡片说明散落材料、学期与年度口径混杂、重复副本、人工归档易错、归档后难追溯等问题，以及系统对应提供的识别、路由、验证、撤销和备份能力。

### 3. 它能做什么

展示六类核心能力：

1. 索引与识别：识别文件名、正文线索、日期和目录上下文。
2. 手动分发：只在本地用户触发后按规则归位，系统不自动移动。
3. 五条时间轴：学期、工作年度、宣传年度、合作年度和长期知识库各归其位。
4. 中转裁决与规则学习：不确定材料进入 `90_中转`，人工纠正沉淀为规则。
5. 验证与撤销：保留操作记录，支持抽样验证、单条和整批撤销。
6. 备份与防误删：同名不同内容保留版本，数据库和配置有本地备份链路。

### 4. 日常怎么用

用只读流程图式文案展示：

`把材料放入 Ding2026 根目录 → 本地系统索引识别 → 用户点击手动分发 → 不确定材料进入中转裁决 → 抽样验证并完成归档`

随后说明首次部署的概念步骤：克隆独立仓库、安装依赖、设置本机材料根目录、启动本地控制台、首次扫描。页面只解释步骤，不提供会执行操作的控件，也不展示真实配置路径。

### 5. 归档架构与安全边界

- 以紧凑表格展示五条时间轴、典型业务和目标区域。
- 以警示卡片强调不自动删除、学期不猜、手工调整优先、重复点击拦截、归档副本校验。
- 目录示意使用通用占位结构，不带本机绝对路径。

### 6. 脱敏状态快照

展示聚合指标和快照时间，并明确“不是实时数据”。允许字段：

- `schema_version`
- `project_version`
- `generated_at`
- `logical_files`
- `instances`
- `pending`
- `invoices`
- `official_docs`
- `operations`
- `root_left`

快照缺失或格式错误时，页面仍展示项目说明，仅显示“状态快照暂不可用”，不得尝试寻找本地数据库或网络数据源。

### 7. 当前限制

如实说明老式 `.doc/.xls/.ppt` 主要依赖文件名、当前无 OCR、AI 预分类默认关闭且需要自行配置兼容接口。不得把规划能力写成已实现。

## 文档与仓库收尾

这是新功能和公开入口变化，因此同步维护 README 与 Change Log，不沿用“小改动不更新文档”的例外。

完成实现后按 neat-freak 完整路径核对代码、文档、规则、远端和工作区。先给出只读清场预览；任何分支、临时文件、旧副本或中间产物的删除，必须在最终汇报后另行获得用户确认。没有删除候选时，只报告工作区与远端状态，不制造清理动作。

## 验收标准

- M20 出现在首页和侧栏首位，链接指向 `pages/19_20_ding2026.py`。
- 用户无需了解源码即可从页面说清项目用途、核心能力和本地使用流程。
- 网站端没有任何会改变文件、配置、数据库或外部状态的操作控件和代码路径。
- 独立 `ding2026-system` 仓库保持原样且仍是唯一源码真相。
- 聚合快照脱敏、静态、可降级，不依赖网络和本机路径。
- 中英文现役文档、默认镜像、导航测试和模块数量一致。
- 相关测试、完整测试和语法检查以当前输出验证通过；若存在既有失败，单独列明，不掩盖。
- 提交并推送后，本地 `main` 与 `origin/main` 一致；线上页面是否已部署和视觉是否符合预期必须标成独立状态，不以代码提交代替上线验证。
