# 问山集 · Wenshanji

同一份输入，交给不同 AI 同时、分别回答，在一个工作台中并排阅读和继续追问。

## 当前工作台

`local-room/` 是当前使用的本机工作台，采用纸感阅读界面：左侧切换会话，上方统一输入，下方并排阅读 GPT、Grok、Gemini 的回答，各自保留独立上下文。Claude 仅预留第四栏，尚未接入。

在 Windows 中双击 [`local-room/start-room.cmd`](local-room/start-room.cmd)，然后打开 <http://127.0.0.1:8766/>。工具箱 M27 同样指向这个本机地址。

支持单栏重试与重新生成、取消、Markdown 阅读与导出、历史会话切换，以及全部会话的备份和恢复。聊天记录保存在当前浏览器中；项目改名继续沿用原存储标识，因此现有记录和旧讨论导出仍可使用。

GPT 使用本机 Codex 登录，Grok 使用本机 Grok 登录，Gemini 通过 Google 官方 Antigravity CLI 的专用配置接入。改名不移动或改写登录凭据。

## 旧版圆桌实验（暂停）

以下为原“众声室” Next.js 概念验证的历史说明。`src/`、`tests/` 和 npm 配置属于这一实验，与上面的 `local-room/` 工作台分别保留。

> 状态：已完成概念验证，2026-08-11 起暂停开发。保留源码和说明，等待以后出现新的实际需求再决定是否恢复。

### 当初想做什么

“众声室”想验证一种多模型圆桌讨论方式：把同一个问题拆成若干立场不同的“席位”，再把席位分配给 DeepSeek、MiMo、Kimi 等模型，让它们以短消息形式接话、质疑、补充和反驳，而不是让一个模型独自生成一篇看似全面的长文。

项目最初希望解决三个问题：

1. 如何避免单一模型沿着同一种思路自我重复；
2. 如何让不同模型承担明确立场，而不是机械轮流发言；
3. 如何把讨论过程保留下来，供后续判断和总结使用。

### 做成了什么

这是一个独立的 Next.js + TypeScript 本地 MVP，没有并入 Streamlit 工具箱。已经实现：

- 话题输入和 JSON 席位池解析；
- 从候选席位中选择 4 至 6 个席位；
- DeepSeek、MiMo、Kimi 配置状态读取；
- 每个模型最多承担两个席位的自动分配；
- 服务端模型调用和不消耗额度的 mock provider；
- 结构化 opening/debate 流程，以及默认使用的 freechat 自由讨论模式；
- 聊天气泡式 transcript、模型状态和局部失败提示；
- 浏览器本地草稿恢复；
- 示例席位池、项目说明和基础使用指南。

### 最后做到什么程度

2026-08-11 最后验证结果：

- 11 个测试文件通过；
- 27 项测试全部通过；
- TypeScript 类型检查通过；
- 源码可以继续恢复开发，但没有部署，也没有形成必须长期维护的实际工作流。

项目暂停的原因不是程序完全不可用，而是当前应用价值不足：多模型自由讨论增加了调用和阅读成本，但尚未证明比直接使用一个模型进行多轮追问更有效。

### 保留边界

- 保留 `src/`、`tests/`、配置文件和本 README，作为概念验证记录。
- `.env.local` 只保存在本机，不提交 Git；其中可能包含模型配置。
- `node_modules/`、`.next/`、`.next-build/` 和 `tsconfig.tsbuildinfo` 都是可再生成缓存，不作为项目成果保留。
- 没有明确的新需求时，不继续增加主持模型、数据库、总结器或部署功能。
