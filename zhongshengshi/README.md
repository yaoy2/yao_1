# 众声室（暂停项目）

> 状态：已完成概念验证，2026-08-11 起暂停开发。保留源码和说明，等待以后出现新的实际需求再决定是否恢复。

## 当初想做什么

“众声室”想验证一种多模型圆桌讨论方式：把同一个问题拆成若干立场不同的“席位”，再把席位分配给 DeepSeek、MiMo、Kimi 等模型，让它们以短消息形式接话、质疑、补充和反驳，而不是让一个模型独自生成一篇看似全面的长文。

项目最初希望解决三个问题：

1. 如何避免单一模型沿着同一种思路自我重复；
2. 如何让不同模型承担明确立场，而不是机械轮流发言；
3. 如何把讨论过程保留下来，供后续判断和总结使用。

## 做成了什么

这是一个独立的 Next.js + TypeScript 本地 MVP，没有并入 Streamlit 工具箱。已经实现：

- 话题输入和 JSON 席位池解析；
- 从候选席位中选择 4 至 6 个席位；
- DeepSeek、MiMo、Kimi 配置状态读取；
- 每个模型最多承担两个席位的自动分配；
- 服务端模型调用和不消耗额度的 mock provider；
- 结构化 opening/debate 流程，以及默认使用的 freechat 自由讨论模式；
- 聊天气泡式 transcript、模型状态和局部失败提示；
- 浏览器本地草稿恢复；
- 示例席位池、项目说明和基础使用指南。

## 最后做到什么程度

2026-08-11 最后验证结果：

- 11 个测试文件通过；
- 27 项测试全部通过；
- TypeScript 类型检查通过；
- 源码可以继续恢复开发，但没有部署，也没有形成必须长期维护的实际工作流。

项目暂停的原因不是程序完全不可用，而是当前应用价值不足：多模型自由讨论增加了调用和阅读成本，但尚未证明比直接使用一个模型进行多轮追问更有效。
