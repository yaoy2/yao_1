# M20 文件分发

M20 的线上说明页和 Windows 本地程序共用本目录的规则。线上不访问个人文件；双击本地入口后，由用户选择材料并确认分发。程序不创建定时任务，不启动常驻服务，不上传文件。

## 使用

程序固定使用 `文件分发_版本号_YYYYMMDD.exe` 命名，当前为 `文件分发_1.5.0_20261102.exe`，更新日期为 2026-11-02。将构建得到的程序放在 `Ding2026` 根目录，与待分发原文件同层。双击后分别勾选“会议纪要”“考勤记录”“月报”“发票”，默认只选纪要和考勤。点击“预览所选规则”，查看去向、勾选可分发文件，再点击“分发已选”并确认。界面实时显示进度、逐项过程及结果；分发是移动，原位置不保留副本。未选规则不处理，预览不修改文件。

原有 `文件分发-纪要_考勤_新闻.bat` 可以先备份，再换为构建目录中的同名兼容入口；它指向本次构建的准确版本文件名，不再调用旧的新闻及固定学期分发逻辑。仓库内的 `legacy_entry.bat` 是构建模板，不应直接复制为成品入口。原始旧脚本保留，当前 M20 不调用它。

整个入口可随 Drive 同步到办公电脑 L。程序按自身所在位置定位源文件夹，不固定盘符或用户名，也不要求 L 安装 Python。先等 Drive 完成同步，再使用；一次只在一台电脑上分发。本地文件锁不等于跨电脑的同步锁。L 的首次实际运行需要在 L 上验收，D 上通过不代表 L 已通过。

| 材料 | 归档位置（相对 Ding2026） |
| --- | --- |
| 校办月报 | `月报/总结月份/校办月报` |
| 学院月报 | `月报/总结月份/学院月报` |
| 系部例会纪要 | `02_学期工作/材料所属学期/03_会议_考勤/党政联席会_系部例会/系部` |
| 学院党政联席会纪要（统一命名PDF） | `02_学期工作/材料所属学期/03_会议_考勤/党政联席会_系部例会/党政联席会` |
| 系部考勤 | `02_学期工作/材料所属学期/03_会议_考勤/考勤记录/系部` |
| 发票 | `07_年度工作档案/开票年份/财务/对应年份发票`，仅使用现有目录 |

月报按总结月份归档，不使用下载时间。10月总结＋11月计划归入10月，7—8月总结＋9月计划归入07-08月。学院月报包括副院长、系主任/部长及副职、管理中心和学工，兼容“学院院报”“工作总结＋计划”。检查当期填写内容，保留整份工作簿及其历史工作表。

系部周材料覆盖医学信息工程系、医学影像系、健康服务与管理系、健康体育部。“会议纪要”同时纳入统一命名的学院党政联席会PDF，形如 `健康学院党政联席会会议纪要-健康学院2026-2027学年第一学期教学第七周.pdf`，兼容 ` (1)` 副本后缀；不纳入其Word稿、考勤表、发言稿及其他会议。按文件名、正文题头及校历核对日期、周次和学期，兼容“会议纪要”“系部例会”和“健服系”简称。2026-09-14至2027-01-15（含）归入2026-2027-1；第1周为9月14—20日，第7周为10月26日—11月1日。仅有周次或月日时按界面显示的本批校历补全，可取消此选项；明确其他学期的材料保留其归属，日期与周次冲突时待核对。完整对应表和项目规则见[校历与学期归档规则](../../docs/guides/m20_school_calendar.md)。只扫描根目录直属文件，不整理已归档目录。

系部纪要分发后统一为 `单位正式名称-会议纪要-第x周`，考勤为 `考勤表-单位正式名称-第x周`；保留原扩展名及大小写。党政联席会纪要保留原文件名。预览显示原名与分发后文件名，只处理本次勾选的材料。周次缺失或冲突时待核对，跨周及考试周、总结周保留真实标识。同批不同内容映射到同名时全部待核对。

同名不覆盖，相同内容不重复搬入，重复源文件仍留在原处。标题、列名或年份冲突，无法据材料和校历确定学期，或当期表为空时，不自动分发。PDF 只读取文字层；扫描件及旧版 `.doc/.xls` 如果文件名不足以确定归属，会保留待核对。月报使用 `.xlsx`；不转换格式或修改正文，月报和发票保留原名。

执行前重新检查文件内容和去向，执行后核对 SHA-256。每次记录位于 `98_系统/文件分发记录`，包含原路径、目标路径、内容摘要和结果。记录与业务材料只保存在个人同步目录，不进公开代码仓库。

只有勾选“发票”时，才对文件名含“发票”或“dzfp_”（不区分大小写）的文件核对票面抬头、号码、日期与金额，不能仅凭文件名归档。确认是发票后自动选入分发，按开票年份放入现有年度财务发票目录。PDF/OFD读取文字层，图片调用本机Windows OCR；票据不上传，语言组件不可用、扫描PDF或内容不明确时保留待核对。单独的说明、申请、清单和开票统计截图不自动搬入。ZIP中逐份核对同年度发票，允许保留带发票号码、开票日期和金额字段的XLSX配套清单，确认后整包归档，不改变包内文件。超过50个文件或解压总量超过100 MiB、混有其他材料、跨年度、缺失目标目录及同名冲突均保留待核对。

图片识别使用[Windows内置OCR](https://learn.microsoft.com/uwp/api/windows.media.ocr.ocrengine.recognizeasync)，不安装语言包或修改系统策略。该规则用于文件归类，不进行税务验真。

## 维护与验证

源代码运行：`python scripts/file_distribution.py --root <Ding2026绝对路径>`。入口始终先预览，命令行没有直接分发选项。

只读验收：`python scripts/file_distribution.py --root <目录> --mode monthly --preview-report <新报告路径>`；`--mode weekly` 检查纪要考勤，`--mode invoice` 只检查发票。`--no-calendar-context` 不为仅含周次或月日的材料套用本批校历。报告只写到显式指定的新文件，不覆盖现有报告。

在 Windows 的项目专用虚拟环境中安装 `build-requirements.txt`，再运行 `python scripts/build_file_distribution.py`。输出位于被 Git 忽略的 `outputs/m20-file-distribution`，包含单文件程序、使用说明与构建清单；构建不自动复制到业务目录或发布。

每次正式更新同时维护 `__init__.py` 中的 `__version__` 与 `__release_date__`，日期表示实际更新日，不以重复打包时间代替。文件名、界面、线上说明、预览报告和分发记录共用这两个值；构建清单还单独记录打包时间。交付时同步新的程序、兼容入口、使用说明及构建清单，旧版本保留恢复副本。

测试使用虚构临时材料；真实样本只读，移动验收仅在副本上完成。线上页面测试使用 Streamlit AppTest，不启动本地 Streamlit 服务。

规则文案的唯一代码来源是 `rules.py`；识别与执行共用 `monthly.py`、`weekly.py`、`engine.py`。修改后重新测试并构建，同步程序和构建清单，避免线上说明与旧程序版本混用。
