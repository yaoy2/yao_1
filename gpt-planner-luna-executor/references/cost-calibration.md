# 成本与质量校准

仅在用户要求比较模型/优化工作流，或反复返工说明现有分工不合适时使用。不要把每个普通任务变成基准测试。

## 按合格任务总成本比较

总投入 = 规划 + 交接上下文 + 执行 + 返工 + 验收 + 浏览器/工具等待 + 用户介入。

至少保留“同一强模型直接完成”和“强模型少量协调 + 指定执行者”两条同条件路线。只比较 Luna 与 Grok 的执行阶段，不能回答是否比主模型全程完成划算。采集整个工作链的可观察用量；主控、网页或子 Agent 任一段未知时，总量也标为不完整。

区分钱、套餐额度、墙钟耗时和成功率，不能混成无单位“成本分”。并行任务的墙钟耗时不是各任务时长之和。只凭便宜的单 token 价格、首次回答速度或一次成功，无法证明整条路线更划算。

缓存输入、普通输入与输出分列；不同服务的 token 统计口径也可能不同，不直接把原始数量相加当成精确的跨服务比较。按可核实的费率另算加权成本，CLI 报价与实际订阅扣费分开。读取运行级最终汇总，不能再把已经包含在汇总中的逐轮 usage 累加一次。

保持代表性样例、原始输入、约束、验收标准和工具权限相同，对各路线使用隔离副本。先用小样本筛除无效路线，需要宣称稳定优势时再按实际任务分布重复。至少覆盖明确小改、含关键不确定性的任务和高返工代价任务后，才讨论通用策略。测试人工干预与准备时间也要记录。

必要字段：任务类型、具体模型/可见网页模式、推理级别、首轮通过/最终通过、失败类别、修复轮次、端到端耗时、可观察的 token/额度/金额、是否人工介入。拿不到用量填 `unknown`；不要用 UI 上的“已登录”或模型清单代替真实调用证据。

基准中某一路线的登录/工具不可用，应标“未运行”，不能判模型能力较差。发生权限阻塞时修复授权或工具前置条件，不升级到更贵模型反复尝试。

## 当前参考，不是永久配置

2026-09-05 核对的本机模型清单含 `gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.6-luna`。主 Agent 不固定为某一代模型，未来调用前以实际可用能力为准。

官方说明将 Astra 定位于最复杂任务，Luna 定位于成本敏感工作负载。Astra 在部分评估中减少输出 token，并不代表在用户的每种任务中总成本必然较低。

- [官方模型指导](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)
- [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
- [Work 与 Codex 额度说明](https://learn.chatgpt.com/docs/pricing)

Work 与 Codex 共用用量体系；Chat 是不同界面和额度口径。网页登录与页面中的模型标签都不能证明使用成本为零。API 定价不能直接换算成 ChatGPT 订阅的实际扣额；Grok 的订阅与用量另行核实。普通执行不需要为了这些参考重复联网。
