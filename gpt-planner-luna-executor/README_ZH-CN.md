# GPT Planner · Luna Executor

**语言**：简体中文 | [English](README_EN.md)

**更新日志**：[中文](CHANGELOG_ZH-CN.md) | [English](CHANGELOG_EN.md)

按任务需要组织 GPT 规划和 Luna 执行的个人 Codex 技能。目标是以合适的准备、交接和验收完成合格任务；没有证据时不承诺省 token 或固定降本比例。

## 何时值得使用

| 请求或任务 | 合适的路线 |
| --- | --- |
| 未指定模型的小改动 | 当前 Agent 直接完成，避免额外交接。 |
| “用 Luna 执行”，目标清楚、执行量较大 | 将范围内探索、实现、检查合并委派给 Luna；不启动网页。 |
| “用 GPT 规划”或“只要方案” | 按明确要求规划，到方案为止，不自动实施。 |
| “GPT 规划后 Luna 执行” | 使用明确要求的网页规划与 Luna 执行路线，保留有效授权和验收要求。 |
| 架构、诊断或关键取舍尚不明确 | 强模型先处理关键不确定性，再决定是否委派。 |
| 明确指定模型、网页或步骤 | 尊重具体指定；不可用时说明受限步骤，不暗中换模型。 |

自然语言触发包括“用 Luna 执行”“用 GPT 规划”“GPT 规划后 Luna 执行”“让 GPT 去做”。讨论这些话、介绍或维护技能不构成实跑授权。Grok 编码交给 [Codex → Grok Builder](../codex-grok-builder/README_ZH-CN.md)。

## 如何协作

主控先确认目标、项目规则、已有修改和关键范围，再给一个简洁任务包：目标、允许范围、必要来源、验收条件、授权和未解决问题。目标、范围、验收明确后停止预读，不先写完整实现再交接，也不逐次监督工具调用。

Luna 在范围内完成定位、修改、测试与普通修复。主控按里程碑或最终结果接收少量证据：变更文件、测试命令及结果、关键差异和阻塞；只有出现新的风险或失败才升级强模型。复用同一任务的上下文和有效授权，相关工作尽量合并交接。

默认不固定 Sol，不强制网页规划，不要求每次任务再跑网页复审。明确要网页时，使用可用的已登录浏览器；登录、账号选择和 MFA 由用户完成。网页能力缺失只阻塞依赖网页的步骤，不把未执行的检查说成失败。

调用技能不扩大项目权限。敏感材料、外部写入、部署和其他需批准的操作遵循当前任务授权与项目规则。明确只规划时不实施；明确委派时不静默由主控包办。

## 安装与验证

将完整的 `gpt-planner-luna-executor/` 复制或安装到各台机器实际使用的 `CODEX_HOME/skills/gpt-planner-luna-executor/`。未设置 `CODEX_HOME` 时，通常是用户目录下的 `.codex/skills/`。更新前核对同名安装并保留本机改动；拉取仓库不会自动更新安装副本，不依赖固定盘符或 Junction。必要时新建 Codex 任务刷新发现。

[SKILL.md](SKILL.md) 是执行入口，[任务包协议](references/packet-protocol.md) 说明交接字段。验证时确认技能可被发现、实际执行模型与请求一致、任务范围和必要检查可核对。只有实际跑过完整串行流程，才能称为完成了“网页规划 → Luna 执行”的闭环。

## 已有证据

2026-09-05 的虚构 `merge_rows` 任务中，Luna medium 首轮通过 12/12 检查、零修复，执行阶段约 22 秒，usage 未提供。ChatGPT 网页可见 `6 Pro` 的独立规划测试约 94 秒。两者是独立通道验证，没有完整网页到 Luna 的串行实跑，也没有全程强模型基线。

总 token、高价模型用量、额度和费用不能混为一谈；比较时应计入主控、准备、交接、修复和验收。以上结果证明相应通道可用，不能据此做费用排名或宣布已经省 token。详见[公开验证记录](../docs/history/2026-09-05-skill-cost-optimization.md)；M22 [线上说明页](https://whatsup.streamlit.app/22_gpt_planner_luna_executor)只展示流程与记录，不调用模型。
