# 115 AI 文件整理系统 · 第一版设计

日期：2026-09-01

## 目标

先把只读系统搭起来，验证 OpenList + 115 Open + 本地索引 + 整理建议可行。不整理 12TB，不修改 115 文件。

## 架构

115 网盘 → OpenList（115 Open 官方驱动）→ 本地 Python 程序 → SQLite 索引 → Streamlit 管理页

## 安全边界

- 第一版只读。
- 禁止删除、批量重命名、批量移动、覆盖文件。
- 禁止修改「云下载」以外的目录。
- 不下载视频内容。
- `WRITE_MODE` 默认关闭；即使打开，第一版也不调用远程写入接口。
- 不实现 delete。

## OpenList

- 官方 Windows 便携版 v4.2.5，安装到 `E:\OpenList`
- 仅监听 `127.0.0.1:5244`
- 使用 115 Open，勾选 OpenList 提供的 OAuth 参数
- 根文件夹 ID 填「云下载」的 cid
- 整理程序使用无写入权限的普通用户

## 未决探测

OpenList `/api/fs/list` 官方公开字段是名称、大小、时间、哈希。115 Open 驱动内部有 Fid，但列表接口不一定透出。授权后先扫最多 50 条探测；没有原生 file_id 时停在 50 条，不用文件名伪装成 file_id。

## 2026-09-01 实机结果

- 115 Open 挂载成功，Root folder id `749127585111375226` 对应网页「云下载」。
- 网页可见约 3616 个文件夹、117 个文件；OpenList 列表为 0。
- 只读账号 `base_path=/云下载` 时，程序必须把逻辑路径 `/云下载` 翻译成 API 路径 `/`。
- 下一步：临时改挂一个小文件夹 cid，先完成 50 条扫描，再考虑云下载根目录。
