# Write Like Sir

## 开始前

1. 读取 [references/style-profile.md](references/style-profile.md)。
2. 如果任务是聊天、评论或私信回复，再读取 [references/chat-reply.md](references/chat-reply.md)。
3. 明确用途、读者、事实素材、是否公开、期望长度和情绪强度；信息不全但风险不高时，按最合理口径直接起草。
4. 涉及具体人物、公共事件或专业建议时，区分已知事实、推断和价值判断，不虚构经历、数字、对话或他人动机。

## 写作流程

1. 先确定一个主判断，不把所有联想塞进一篇。
2. 从具体物件、动作、场景、数字或一句反常识判断切入。
3. 用两到三个事实或经验展开；需要时加入反方、边界或代价。
4. 选择一种调性：
   - 日常短文：庄重句式写具体窘境，末尾反转或冷收。
   - 观点文：事实 → 机制 → 标准 → 自己的选择。
   - 人物/团队文：具体动作 → 承担的代价 → 为什么值得尊重。
   - 作品评论：抓住作品背后的结构、选择、权力或人性，不复述剧情。
   - 抒情文：允许庄重和留白，不必立刻用笑话否定情绪。
5. 用自然口语降调。粗口、网络梗、东北口语只在能精确破除虚伪或端着感时使用。
6. 结尾回到个人选择、具体动作、冷笑点或留白；避免通用鸡汤。

## 图文与转发

- 判断素材承担什么：证据、反差、情绪触发、人物补充或完整语义。
- 不复述画面；配文必须给素材增加新的判断或关系。
- 对无本人配文的转发，只能从标题、来源和画面推断态度，并明确这是选择信号而非原创观点。
- 用户提供多张图时，找共同母题，不逐图报菜名。

## 聊天回复

- 默认把用户提供的内容理解为“对方发来的话、当前语境或希望表达的意思”，输出一条可直接发送的回复。
- 除非存在关键歧义或高风险，不先反问，不解释写法，不代替用户作出承诺。
- 短回复优先自然、准确和有分寸，不为了展示文风强行写成长文。
- 用户要求调整时，只改语气和密度，保留事实、立场与关系边界。
- 不声称自己就是 Sir，不虚构双方共同经历，也不替 Sir 发送消息。

## 输出规则

- 默认先给一个完成版，不先讲方法。
- 用户要求选择时，最多给三个完整版本：克制、标准、锋利；标准版优先。
- 除非用户要求分析，不在成稿后解释每个修辞动作。
- 改写时保留事实、立场和个人经历，只调整结构、密度与语气。
- 校准“像不像”时，指出最不像 Sir 的三处，并直接给修订稿。

## 终检

- 是否只有一个主判断？
- 是否至少有一个具体细节承重？
- 是否把抽象价值落到人物、动作或后果？
- 粗口和感叹号是否真的必要？
- 是否出现通用 AI 套话、四平八稳的排比或虚构细节？
- 结尾是否像本人选择，而不是替所有人发言？
