# Deepself

`Deepself` 是一个以本人长期朋友圈为材料的个人表达研究项目。

它不是普通的“朋友圈备份”，也不是简单统计高频词。这个项目把本人配文、图片、视频、音乐、转发内容及它们之间的关系放在一起观察，用来回答三个问题：

1. 我的文字有什么稳定特征，优势和问题分别是什么？
2. 从早期到近期，我关注的内容、表达方式和价值判断发生了什么变化？
3. 能不能把这些真实特征沉淀成一个可复用、但不机械模仿口头禅的个人表达 Skill 和对话工具？

## 项目是怎么来的

最初的目标是读取本人已登录的桌面微信朋友圈，以全部历史内容为数据源，完成行文分析、风格演变分析和个人文案 Skill。

执行过程中，任务口径经过了几次关键修正：

- 一开始只关注朋友圈文字，后来确认这不够。很多内容必须结合配图、视频、音乐或转发文章才能理解真正的语气、观点和审美。
- 曾考虑跳过“只有转发、没有配文”的朋友圈，后来决定保留。主动分享什么，本身也代表当时的兴趣、态度或价值选择。
- 曾讨论追溯到 2015 年，最终把正式采集范围确定为 **2019-01-01 至采集当日**；2018 年及更早内容不纳入本项目。
- 分析时必须区分“本人写了什么”和“本人选择分享了什么”，不能把第三方文章标题、歌词或引用冒充本人的原创文风。

因此，本项目最终采用“文字 + 视觉 + 分享选择 + 时间变化”的整体分析方法。

## 数据是怎么采集的

采集来源是本人已经登录的 Windows 桌面微信“朋友圈/相册”页面。

采集方式不是读取微信本地数据库，也不是调用微信接口，而是从最新内容开始向前翻页，逐条打开详情页并进行视觉核对：

- 记录发布时间和本人配文；
- 判断是原创、引用、转发还是无配文分享；
- 记录文章、音乐或视频卡片的标题与来源；
- 概括图片或视频关键画面；
- 判断文字与素材之间是补充、反差、证据、情绪触发还是完整语义关系；
- 只有理解原帖确有必要时，保留本人的补充回复，不以分析好友为目的；
- 保存详情页截图作为核对依据。

整个采集过程只读，不点赞、不评论、不转发、不发布，也不修改微信设置。

## 已经完成的成果

### 1. 结构化朋友圈数据

文件：[`data/private/moments.jsonl`](data/private/moments.jsonl)

每行是一条 JSON 记录。由于采集过程跨越多个阶段，部分早期字段命名存在差异，但核心信息包括：

- `published_at`：发布时间；
- `text`：本人配文；
- `authorship`：原创、引用、转发或纯分享等归类；
- `media_type`：图片、视频、音乐、文章卡片等；
- `visual_summary`：视觉内容概括；
- `text_media_relation`：文字和素材之间的关系；
- `shared_title`、`shared_source`、`shared_creator`：分享内容信息；
- `own_replies`：确有语境价值的本人补充回复；
- `location`：原帖显示的位置；
- `screenshot`：对应核对截图；
- `collection_status`：采集和视觉复核状态。

这个文件是后续统计、复核和重新分析的主要数据源，不应直接提交到 Git。

### 2. 原始核对截图

目录：`data/private/screenshots/2026/`

目录名 `2026` 表示本轮截图采集发生在 2026 年，不表示里面的朋友圈都发布于 2026 年。文件名中的日期才是朋友圈发布时间。

截图用于确认：

- 日期有没有读错；
- 同一天的多条朋友圈是否被拆开；
- 长文、图片、视频和转发卡片之间是什么关系；
- 结构化数据出现疑问时能否回到原画面复核。

截图包含私人信息，只能保存在本机私密目录。

### 3. 行文风格画像

文件：[`reports/private/01_行文风格画像.md`](reports/private/01_行文风格画像.md)

核心判断是：本人的文风以判断为骨架，以真实经验和责任感为重量，再用东北口语、网络梗、英文短语、粗粝表达和自嘲拆除“端着感”。真正情绪浓重时，文字反而会转向克制、庄重和有节奏的短句。

报告同时整理了：

- 稳定的价值底色和语言指纹；
- 图文、视频和转发素材的使用方式；
- 文风优势；
- 判断先行、支线增殖、粗口遮蔽论证等风险；
- 适合本人的改进原则和文案类型。

### 4. 风格演变时间线

文件：[`reports/private/02_风格演变时间线.md`](reports/private/02_风格演变时间线.md)

整体变化不是从“不会写”变成“会写”，而是：

> 借作品说话 → 用经历说话 → 用承担过的责任说话 → 反过来审视自己的标准。

大致阶段如下：

- **2019**：引用、策展式转发、短评和短反转较多；
- **2020**：公共事件推动长文和价值判断系统成形；
- **2021**：专业身份、金融经验和社会观察合流；
- **2022**：表达更日常、更自嘲，但判断意识没有消失；
- **2023**：记忆、教育和组织意识上升；
- **2024**：从外部评论者逐渐转为组织中的实际承担者；
- **2025**：写作更向内，故乡、记忆和自我对峙增强；
- **2026**：形成相对稳定的“判断—责任—自省”体系。

### 5. 个人文案 Skill

目录：[`skill/write-like-sir/`](skill/write-like-sir/)

主要文件：

- [`SKILL.md`](skill/write-like-sir/SKILL.md)：触发范围、写作流程和终检规则；
- [`references/style-profile.md`](skill/write-like-sir/references/style-profile.md)：价值底色、语言指纹、常用结构和禁忌；
- [`agents/openai.yaml`](skill/write-like-sir/agents/openai.yaml)：Codex 中显示的名称和默认提示词。

Skill 的目标不是给所有文章机械加粗口、反问句或“东北味”，而是保留更深层的写作方式：

- 先确定真实判断；
- 用具体细节和亲身经验承重；
- 说清角色、机制、代价和后果；
- 用自然口语降调；
- 最后回到自己的选择、动作或留白。

`skill/write-like-sir/` 是项目内的源副本，已同步安装到 `E:\codex\.codex\skills\write-like-sir`，可由 Codex 自动发现或通过 `$write-like-sir` 明确调用。以后修改源副本后，应重新校验并同步安装目录。

## 以后怎么使用

### 打开 Deepself 对话框

双击 `启动Deepself对话框.bat`，或在仓库根目录执行：

```powershell
python -m streamlit run Deepself/app.py
```

对话框默认使用 DeepSeek，也可以切换到 Kimi 或 GLM。页面只读取环境变量或 Streamlit Secrets 中的密钥：

- DeepSeek：`DEEPSEEK_API_KEY`
- Kimi：`MOONSHOT_API_KEY` 或 `KIMI_API_KEY`
- GLM：`GLM_API_KEY` 或 `ZHIPU_API_KEY`

密钥不会写入代码、聊天记录或日志。对话历史只保存在当前页面会话中；发送给模型的消息和抽象风格画像仍会经过所选 API 服务商。531 条朋友圈原文、截图和私密报告不会被应用读取或上传。

输入可以是对方刚发来的消息、双方关系、聊天背景，或者本人希望表达但尚未组织好的意思。默认返回一条可直接发送的标准版，可以继续切换成“更克制”“更自然”或“更锋利”。模型名允许手动修改，便于供应商升级后调整，不必改代码。

### 让 Codex 按本人语感写文案

可以明确指定项目内 Skill，例如：

```text
使用 Deepself/skill/write-like-sir，结合这张图和下面的事实，替我写一条朋友圈。
不要虚构细节，先给标准版；如果有必要，再给一个更克制的版本。
```

也可以让它做校准：

```text
使用 write-like-sir 检查这段文字像不像我。
指出最不像我的三处，再直接给修订稿。
```

### 继续补充新朋友圈

如果以后要把 2026-08-04 之后的新内容加入项目：

1. 只从现有最新记录之后开始，不要重采已经校验过的 531 条；
2. 延续 `moments.jsonl` 一行一条 JSON 的方式；
3. 保存详情截图并建立相对路径；
4. 区分本人原创和选择分享；
5. 每批检查 JSON 坏行、重复发布时间、最早和最新日期；
6. 更新 `collection_checkpoint.md` 和本 README 的数据统计；
7. 新数据积累到足够规模后，再更新风格报告和 Skill，不要因一两条偶然表达就改写整体画像。

### 重新分析

重新分析时，至少分成三层：

1. **原创文字层**：只研究本人真正写下的文字；
2. **素材关系层**：研究配文如何解释、反转或补充图片、视频和音乐；
3. **选择偏好层**：研究无配文转发所代表的主题、观点和审美，但不将第三方文风归到本人名下。

- `data/private/` 和 `reports/private/` 已由 `.gitignore` 排除；
- 朋友圈原文、截图、头像、姓名、位置和私密分析不得推送到远端；
- `skill/write-like-sir/` 只保留抽象后的写作原则，不包含朋友圈原文，可作为可复用成果单独管理；
- 本项目没有从微信删除、修改或发布任何内容；
- 私密目录只保存在本机意味着存在硬盘损坏或误删风险。若这些资料需要长期保留，应使用本人控制的加密本地备份或可信私人存储，不能依赖 GitHub 仓库恢复。

提交 Git 前应检查：

git status --short -- Deepself

## 已知限制

- 数据反映的是采集时本人账号在桌面微信中能够看到的内容；已经删除、不可见或未加载成功的内容无法证明存在与否。
- 采集依赖逐条视觉核对，不是微信官方导出；极少数字词、表情或来源名称仍可能存在人工识别误差，可通过对应截图复核。
- 视频只记录关键画面和与配文相关的语义，没有逐帧保存完整视频内容。
- 早期记录经过多轮采集，个别 `authorship`、`media_type` 字段命名存在历史差异。进行程序化统计前应先做字段归一化，不要直接把不同标签视为不同人格特征。
- 当前 Skill 来源于朋友圈表达，适合个人文案、评论和复盘，不应未经调整就用于正式公文、法律意见、医疗建议或对外组织声明。
