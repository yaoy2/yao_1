# 存储分析

默认读取目录元信息并生成静态 HTML 报告。扫描源只读；输出文件写入当前任务目录。保留现有扫描、报告和可选清理脚本，不把“可再生”当作自动删除授权。

## 范围与运行时

- 从请求确定目标磁盘或目录。明确只查某处时，先做该处的只读统计；不要为套用脚本而扫整个用户目录。
- scripts/scan.py 无路径参数，默认扫描系统信息与常见占用热点。只在请求范围包含这些位置时使用；它不等于逐文件扫描所有盘符，也不要给它编造 --root 参数。
- Windows 使用 load_workspace_dependencies 返回并核对的 C 盘 Python；不改系统 PATH、不安装新的系统 Python。当前 bundled Python 为 C:/Users/Yao/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe。
- 临时扫描数据位于 C:/Users/Yao/.codex/tmp 下的本次任务目录；交付报告遵从用户指定位置，否则放 C:/Users/Yao/Documents/Codex 的任务目录，文件名加日期。不要覆盖其他任务的文件。
- macOS 使用当前已验证的 Python 与系统工具。脚本均只依赖标准库。

## 扫描与判断

1. 记录扫描范围与时间。需要热点扫描时，以绝对路径执行 scripts/scan.py，把标准输出保存为 UTF-8 JSON。
2. 阅读对应的 [Windows](references/windows.md) 或 [macOS](references/macos.md) 数据布局参考；只读当前系统所需文档。
3. 核对占用最大的几项、单位、实际路径和目录用途。必要时向下一层定向检查；不读取与任务无关的用户文件正文。
4. 访问被拒、链接跳过、扫描期间变化和过滤门槛都属于覆盖限制。未知项保留未知，不把“未统计”写成 0。
5. 同一路径、父子目录及别名可能重复出现在各组。估算总释放量前去重，不能把嵌套大小直接相加。

## 分类原则

- **绿：确认可再生的候选缓存。** 必须核对具体子路径和用途；给估算空间、必要的关闭步骤和受支持清理方式。整个 .cache、Codex 运行组件、浏览器用户档案或应用数据库不能仅凭目录名归绿。
- **黄：含用户数据或用途待判断。** 说明数据类型与实际可行的处置路径；无证据时不要给一键删除目标。
- **红：应由应用或系统管理的内容。** 给正规卸载或系统清理入口，不手删系统文件、正在使用的数据库或唯一资料。
- 大小与可释放量标明估算；不要给每项固定的说明句数，也不靠颜色保证清理安全。

## 默认生成静态报告

以 scripts/build_report.py 顶部现有 schema 为准写 analysis JSON，再执行：

```powershell
# 先用依赖加载器确认这两个路径，并按实际任务设置已存在的输出目录。
& $storagePython $storageReportBuilder $storageAnalysisJson $storageReportHtml
```

变量分别是已验证的 Python、技能目录下 scripts/build_report.py、分析 JSON 与最终 HTML 的绝对路径。静态报告无需 trash_paths，DELETE 配置应为 null，不启动服务、不调用清理接口。用当前文件预览或浏览器打开报告。

报告展示实际占用、优先候选、分级依据和长期建议；保留模板需要的数据字段，不强制添加无用卡片。简要结论与关键覆盖限制放在聊天中，避免重复报告全文。

## 用户明确要求执行清理时

- 先核对具体目标、动作和现有授权。任务已明确授权的范围不重复索要相同确认；新发现或范围不明的对象不能直接加入。
- 脚本支持的范围不是授权范围。执行前验证绝对路径、重解析点、实际数据用途、恢复可能及当前占用进程。
- 优先使用应用自带清理或可恢复方式；永久删除只在明确授权覆盖该动作时使用。
- 仅用户需要网页清理且已授权目标时才考虑 scripts/server.py。保留其 localhost、token、Host、realpath 和分级白名单检查，不为了通过错误放宽根目录。
- 当前服务支持范围受代码约束，不能承诺 Windows 任意盘符或系统目录都可清理。目标不受支持时改用本来就获准且范围可核验的方式，或报告限制。
- 后台启动使用隐藏窗口；仅管理本任务启动的服务，完成后关闭它。
- 不在技能维护或只读分析中测试真实删除；需要验证清理逻辑时只用隔离的测试文件。

## 验收

核对报告中的路径与数值、嵌套去重、覆盖范围和只读模式；打开报告检查内容可读。清理任务另核对实际影响和失败项。分别说明已验证的扫描/报告行为与未验证的清理平台能力，不沿用旧版本的“全平台通过”说法。
