# 制作高端 PPT

## 核心契约

1. 先读取并完整遵守可用的 `presentations:Presentations` 技能，把它作为 PPT 文件制作和技术质检引擎；若该技能不可用，说明文件制作的阻塞，继续可独立完成的素材审计、叙事设计和页面蓝图，不得改用 `python-pptx` 或整页图片糊成 PPT。
2. 新建演示文稿或重构全稿时，先完成素材审计、叙事设计和页面蓝图，再开始排版。定向修订已有成稿时，复用已确认的任务规格、素材来源和设计规则，只补查相关材料与受影响页面，直接进入修改及对应质检，不重启全套策划。用户明确只要大纲或方案时，在页面蓝图处停止。
3. 默认以用户指定页数为目标，允许范围为目标页数上下各一页；用户说“必须正好 N 页”时不得浮动。发生浮动必须在交付时说明原因。
4. 保持文字、图片、表格和图表尽可能原生可编辑。不得把整页渲染成一张图片来伪装完成。
5. 不编造事实、数据、案例、引用、机构标识或成果。对冲突或缺失的关键事实标记来源与假设。
6. 用户模板、字体、字号、颜色、图片和禁用项优先于默认设计判断。
7. 首次正式成品交付前必须逐页全尺寸检查，并通过溢出、占位符、适用的模板保真和 PowerPoint 实开验证；后续局部修订按变更影响复检并复用未变化部分的有效检查结果。任何适用的关键门槛未通过都不得宣称最终完成或交付为正式成品。

## 工作流

### 1. 建立任务规格

读取 [intake-and-brief.md](references/intake-and-brief.md)，形成内部任务简报。至少确认或推断：受众、场景、沟通目标、页数、画幅、模板、字体、必须使用的内容与图片、禁止项和交付格式。

信息不完整时按合理默认值继续，并在进度更新中简短说明假设。先查素材和上下文；只有无法可靠解决且会显著改变结论的关键缺口、已发现的素材授权缺口或身份事实冲突，以及尚未获准的外部操作才询问。暂停依赖该答案的步骤，继续其余已授权工作；不因可能公开使用而暂停本地制作。

开始时检查制作、渲染和 PowerPoint 实开所需能力是否可用。能力缺失只阻塞依赖它的步骤，继续独立的制作与检查；分别记录“检查未执行”和“检查失败”，不把工具缺失当成文件损坏，也不将未实开的文件称为正式验收通过。

### 2. 审计全部素材

完整制作时先读完本次相关素材，再开始制作页面；定向修订只补查受影响内容及必要上下文。建立或更新以下内部清单：

- 事实、数字、日期、专有名词及其来源；
- 核心观点、证据和可删减内容；
- 重复、矛盾、过期或缺少依据的内容；
- 表格和图表候选；
- 图片清单、分辨率、方向、主体位置和使用限制；
- 必须保留的原话、标识、页脚或品牌元素。

把中间记录放入当前演示文稿任务的 scratch workspace，不污染项目目录。

### 3. 设计叙事和页面蓝图

读取 [narrative-and-page-blueprint.md](references/narrative-and-page-blueprint.md)。先写一句沟通任务：

> 汇报结束后，目标受众应当理解、相信、决定或采取什么行动，因为哪一条核心结论成立。

选择适合场景的叙事弧，为每页规定清晰任务及适合内容的标题。新建或全稿重构时逐页建立蓝图，列出页码、主题或结论、证据、视觉形式、素材来源和预计密度；定向修订只更新受影响页面，不为未改变的页面重建蓝图。

页面数超出允许范围时，按以下顺序处理：删除重复信息、合并相邻论点、把次要细节移入备注、拆除低价值图表。不得依靠缩小字号硬塞内容。

### 4. 锁定视觉路线

读取 [visual-system-and-assets.md](references/visual-system-and-assets.md)，只选择一条路线：

1. 用户提供 PPT 或明确模板：严格模板复用，复制合适的源页面并编辑继承对象。
2. 用户提供参考图、品牌规范或明确风格：从零建立与要求一致的视觉系统。
3. 用户没有视觉方向：使用基础 Presentations 技能提供的默认高质量布局体系。

在制作前锁定：画幅、背景、字体层级、主辅色、网格、边距、图片处理方式、图表风格和页码规则。整套 PPT 保持同一设计语言，同时变化页面轮廓和节奏。

### 5. 处理图片和数据

图片使用顺序：用户指定图片 > 用户材料中的真实图片 > 官方或可信公共图片 > 适合抽象概念的生成图片。

先根据页面版式确定图片框比例和视觉重心，再选择或生成图片。尊重人物朝向、主体位置和裁切安全区。禁止拉伸、低清放大、重复图片充数以及伪造真实人物、产品界面、官方标识或证据。

数据先核算再设计。图表标题直接表达结论；只保留帮助受众判断的维度、图例和标注。不得把复杂 Excel 截图直接当图表使用。

### 6. 制作可编辑成稿

使用基础 Presentations 技能规定的实现方式和 workspace 约定。

- 有模板时，完整检查所有源页面，建立页面映射，复制源页面并编辑继承对象；不得在模板上覆盖一套平行设计。
- 无模板时，按页面蓝图选择不同但协调的版式，避免连续多页使用同一构图。
- 先精简文字，再调整布局；最后才考虑字号。不得低于用户或模板规定的字号下限。
- 演讲备注只包含有助于讲述的补充信息，不暴露内部制作说明。

### 7. 逐页质检和修复

读取 [qa-and-delivery.md](references/qa-and-delivery.md)，依次完成：

1. 渲染全部页面并逐页全尺寸查看；
2. 查看整套缩略图，检查节奏和一致性；
3. 修复遮挡、溢出、异常换行、密度失衡、图片裁切和对齐问题；
4. 核验页数、字体、图片、表格、图表、来源与可编辑性；
5. 有模板时运行模板映射和模板保真检查；
6. 检查最终 PPTX 中不存在空结构占位符或默认提示文字；
7. 使用 Microsoft PowerPoint 只读打开，确认文件、中文、字体和媒体正常。

首次成稿执行上述全部检查。后续修订合并一批相关修改后，统一渲染并检查受影响页面，复用未变化页面的有效检查结果，并核对最终文件可打开、页数与对象完整性；结构、模板或全局样式改变时重新渲染全套，并重做受影响的全局检查。整套缩略图复用未变化页面的渲染结果，只在页面内容、顺序或视觉变化后更新并检查，不在每个对象改动后重复检查。

### 8. 交付与修订

最终回复先给结果，再简要说明：页数、模板或视觉路线、字体、图片数量、完成的关键验证、页数浮动或其他偏差。只交付用户需要的成品，不附带 scratch 文件、检查日志或内部脚本。

后续修改分为三类：内容、结构、视觉。优先只改受影响对象和页面，保留已确认的内容与设计规则；每轮修改后重新执行相应质检。
