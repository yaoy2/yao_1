## 素材提炼

把素材整理为四层：

1. 事实：数字、日期、名称、政策、事件和已发生结果；
2. 观点：素材作者的判断或主张；
3. 证据：支撑观点的数据、案例、图片和引用；
4. 动作：需要受众批准、选择、执行或记住的事项。

对每条重要内容记录来源。冲突内容并列标记，不擅自选择对用户更有利的版本。

删除：重复表达、无法支撑核心结论的细节、空泛口号、同义堆叠和只为填版面的数据。

## 常用叙事弧

根据沟通任务选择一条主线：

- 行政汇报：背景与任务 → 当前判断 → 已采取行动 → 结果与问题 → 下一步；
- 工作总结：目标 → 关键动作 → 结果证据 → 经验判断 → 后续安排；
- 项目申报：真实需求 → 解决方案 → 差异化能力 → 实施路径 → 预期价值；
- 竞赛答辩：痛点 → 洞察 → 方案/产品 → 验证 → 价值与增长；
- 教学培训：问题 → 原理 → 方法 → 示例 → 应用；
- 决策建议：问题 → 选项与标准 → 比较 → 推荐 → 风险与行动；
- 技术说明：问题 → 机制 → 架构/流程 → 验证 → 边界与使用方式。

不要用“目录”代替叙事。相邻页面应当存在问题—回答、原因—结果或判断—行动关系。

## 页面蓝图

每页写一行：

```text
页码 | 页面任务 | 标题 | 核心证据 | 视觉形式 | 素材来源 | 密度
```

约束：

- 一页围绕一个主要主题或结论；
- 背景、定义、流程等页面可用准确的主题标题；证据支持明确发现时采用结论型标题，不为标题形式编造判断；
- 图表、表格和图片直接服务当前页面任务；
- 开场说明为什么值得听；
- 结尾解决开场提出的问题，并明确行动、决定或应用；
- 不以“谢谢观看”替代结论页。

## 页数控制

先为开场、核心论证和结尾分配页数，再分配细节。目标为 N 页时：

1. 先生成 N 页蓝图；
2. 若信息过多，先删重复和低价值细节；
3. 再合并同一论点下的相邻证据；
4. 把补充解释移入备注；
5. 仍无法容纳时，使用 N+1 页并记录原因；
6. 素材不足时，扩大关键案例或解释，而不是制造空洞页面；必要时使用 N-1 页。

用户说“正好 N 页”时，只能在 N 页内重新组织，不得浮动。

## 文案和密度

- 先写结论，再选版式；
- 先删字，再缩字号；
- 避免整段搬运 Word 原文；
- 列表通常控制在 3—5 项；
- 每项使用具体动词和对象；
- 数据旁边写出它意味着什么；
- 避免重复使用“从 A 到 B”“赋能”“全面提升”等模板化口号；
- 页面标题不得意外换行，除非版式明确设计为多行标题；
- 主视觉页面降低文字密度，数据页面降低装饰密度。
