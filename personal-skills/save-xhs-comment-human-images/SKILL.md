# 保存小红书评论区真人图片

## 目标

使用可控浏览器完整遍历小红书笔记评论区。对每张评论图片先打开预览并进行视觉判断，只有符合“真人主体”标准时才点击下载。不要先下载再清理。

## 浏览器与登录

- 使用当前可用的 Browser/Chrome 浏览器控制能力，并先完整遵循对应浏览器控制 Skill。
- 默认优先使用 Codex 内置浏览器，以复用其独立且可持续保存的登录状态；用户明确指定 Chrome 时遵从用户选择。
- 复用现有小红书登录状态。不要读取 Cookie、本地存储、密码或其他账号数据。
- 页面要求登录时，将浏览器显示给用户，只让用户完成登录或验证码；完成后继续自动操作。
- 不要用网页搜索、外部抓取或未登录请求替代用户指定的浏览器页面。
- 不要主动退出账号或清除浏览器数据。

## 图片筛选标准

### 下载

- 真实人物是画面的主要视觉主体。
- 不要求露脸；真人全身、半身、胸肩、躯干等明确的人体主体均可保留。
- 真人照片即使含有字幕、背景文字、水印或少量贴纸，也保留。
- 真人主体被少量卡通贴纸遮挡时，只要真实人物仍是主要内容，也保留。

### 不下载

- 画面没有真人主体，例如纯文字图、聊天截图、动物、物品、设备、风景或室内环境。
- 卡通、动漫、插画、表情包、游戏人物或 CG 人物是画面主体。
- 只有手、物品或屏幕等局部内容，无法判断真实人物是主体。

### 不确定

- 无法可靠判断时不要下载，将其计入“待人工确认”。
- 只根据图片内容判断，不要根据评论者昵称、文件名或评论文字推断。

## 工作流

1. 记录任务开始时间和浏览器当前下载目录，不改动已有文件。
2. 打开用户提供的小红书笔记链接，确认进入目标笔记详情页并识别登录状态、笔记标题和评论总数。
3. 锁定评论区和评论滚动容器。只处理评论正文中的图片，排除头像、笔记正文图片、表情图标、二维码和页面装饰。
4. 从上到下遍历评论：
   - 展开当前区域所有“展开 N 条回复”“展开更多回复”等回复入口，再处理其中的图片。
   - 分段滚动评论容器，等待动态内容加载后再继续。
   - 记录已经见过的评论图片标识；忽略 CDN 临时时间戳和缩放参数，避免同一图片重复处理。
   - 至少连续五次滚动或展开后，评论数量、唯一图片集合和滚动高度都不再变化，且没有剩余可展开回复，才视为到达末尾。
5. 对每张未处理的评论图片执行：
   - 点击评论缩略图，等待放大预览完整加载。
   - 观察放大图，按照“图片筛选标准”分类。
   - 符合标准时才定位当前预览工具栏的下载按钮并点击；不要仅凭固定坐标操作，除非已用当前截图验证坐标。
   - 不符合或不确定时关闭预览，不触发下载。
   - 记录结果为“已保存”“已跳过”或“待人工确认”，并记录跳过原因。
6. 每次下载后确认出现新的完整文件，再关闭预览并继续。处理同一笔记时不要重复下载相同图片。
7. 完成后只检查本次新增文件：验证文件数量、大小和可读取性。不要删除、移动或重命名用户已有文件。

## 异常处理

- 出现验证码时请求用户处理，不绕过验证码。
- 浏览器连接中断时保留已完成结果，恢复后从已记录的图片集合继续。
- 评论区持续新增时设置合理的稳定检查，不因一次到底就提前结束。
- 下载按钮不可定位时重新读取当前页面状态或截图，不使用过期定位信息盲点。
- 单张图片失败时记录失败原因并继续其他图片；任务结束时明确列出失败数量。

## 完成报告

报告以下内容：

- 笔记标题和评论总数；
- 发现的唯一评论图片数量；
- 已保存数量；
- 已跳过数量，并按“无真人主体”“卡通/插画主体”等原因汇总；
- 待人工确认和失败数量；
- 下载目录；
- 登录状态是否已保留，以及是否存在未展开或未完成的评论内容。
